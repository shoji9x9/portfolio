# 動作特性の主張と判断材料は、推論でなく実測を根拠に出す

## 事象

Node 26 更新（Issue #45）で、`@types/node` の minor 差について 2 度、未実測の主張をした。

1. **「型の minor 先行は危険 / 型が古いのは安全側」と断定して選択肢の説明に書いた。**
   根拠は semver の一般的な性質からの推論だけで、測っていなかった。ユーザーの
   「『型のマイナーが実行環境より古い』のは安全側な理由がわかっていません」で発覚した。
   後から測った結果は主張と一致したが（`@types/node` 26.0.0 → 26.1.1 の差分に
   `crypto.randomUUIDv7` / `diagnostics_channel.boundedChannel` / `node:ffi` が入り、
   Node 26.0.0 には無く 26.5.0 にはある。型が先行すると `tsc` は通り実行時に `SyntaxError`）、
   **提示した時点では根拠を持っていなかった**。

2. **選択肢を 3 度提示し、2 度 clarify で返された。** ユーザーが直接
   「現在のロジックはどうなっているのでしょうか？型が古い場合は green でしょうか？」と
   聞くまで、**現状の判定表を出していなかった**。判定マトリクスを実測して出した直後に
   「片側制約に拡張して下さい」と即決している。必要だったのは選択肢の増量ではなく
   現状の実測値だった。

## 根本原因

なぜ未実測で断定したか → 「メジャーで起きることは minor でも同じ」という semver の類推が
自明に思え、検証対象と見なさなかった。

なぜ検証対象と見なさなかったか → 選択肢の説明文を「背景説明」と位置づけており、
**ユーザーの意思決定を左右する主張**として扱っていなかった。

なぜそう位置づけたか → **AGENTS.md「調査と実験」の射程が「原因調査で仮説を『否定した』
『一致した』と結論する前に」に限定されており、「設計判断の根拠として動作特性を主張するとき」
「ユーザーへ選択肢の判断材料を提示するとき」が文面に含まれていなかった** ← 根本原因

KEDB 照合: [[2026-07-29-verify-under-observed-conditions]]（status: applied）と同型の再発。
あちらは原因調査での結論、今回は設計判断の根拠と提示物。同じ「測らずに言い切る」構図が、
既存規律の射程外で再発した。applied なので追記せず、恒久側（AGENTS.md）を直接拡張する。

## 横断スコープ

同じ構図は、トレードオフや選択肢の提示、コード・ドキュメントに書く「〜なので安全」「〜は問題
ない」という断定、PR 本文の根拠記述、レビュー所見の「実在する / しない」判定にもある。いずれも
「もっともらしい推論」を「測った事実」と同じ強さで書いてしまう点が共通。

本セッションではもう 1 例あった。`outdated.yml` の本文生成を actionlint が通った時点で
妥当と扱いかけたが、AGENTS.md「成功したチェックは実行の証拠ではない」に従いフィクスチャーで
実際に流した。既に明文化されている規律は機能した——射程が書かれていない領域だけで滑った。

## 提案

動作特性を断定するときと、ユーザーへ選択肢の判断材料を出すときは、推論ではなく実測を根拠に
する。変更後の想定だけでなく **「現状の挙動」も測って併記する**。選択肢を増やす前に、現状が
どう振る舞うかを示す。

今回有効だった具体形: **同じマトリクスで現状と変更後を並べて示す**（ケース × 入力 × 判定）。
これを出した直後にユーザーは即決した。

反映先: AGENTS.md「調査と実験」節を、原因調査に限定しない形へ拡張する。

## 適用（2026-08-03）

AGENTS.md「調査と実験」節に、原因調査に限定しない適用範囲を追記した。`.agents/rules/` に
しなかったのは、この規律が特定パス配下に閉じないため（主張や選択肢の提示はファイルを 1 行も
編集せずに起きる。rule は `paths` にマッチしたファイルを編集するときだけロードされる仕組みで、
`**` にしても常時ロードされない）。既存の「調査と実験」節へ追記したのは、根本原因が
**その節の射程が狭かったこと**そのものだったから。別節を作ると同じ射程漏れを再生産する。

機構化はしていない。「主張が実測に基づくか」を決定論的に検査する手段が無い（成果物には結論だけが
残り、根拠を測ったかは残らない）。実際に検出したのはユーザーの指摘で、
[[2026-07-29-verify-under-observed-conditions]] / [[2026-08-03-early-exit-guard-changes-teardown]]
と同じくレビュー・指摘の運用がこの種の誤りに効いている。

なお本セッションでは、既に明文化されている規律（「成功したチェックは実行の証拠ではない」）は
機能した——`outdated.yml` の本文生成を actionlint 通過で済ませず、フィクスチャーで実際に流した。
滑ったのは射程が書かれていない領域だけで、明文化の効き方を裏づけている。
