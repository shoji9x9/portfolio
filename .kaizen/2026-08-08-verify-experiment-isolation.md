# 実験は「隔離したつもり」ではなく、隔離が成立したことを測ってから流す

## 事象

Issue #59（js-yaml）の作業中に nanoid の脆弱性を調べるため、`package.json` / `pnpm-lock.yaml` /
`pnpm-workspace.yaml` を一時ディレクトリーへ複製し、「本体は無変更」の前提で依存解決を実験した。
実験は `mise -C <本体パス> exec -- pnpm update nanoid ...` の形で実行した。

結果、2 つの誤りが同時に起きた。

1. **本体リポジトリーが汚染された。** `-C` は cwd 自体を本体へ変えるため、pnpm は複製先ではなく本体に
   対して実行され、本体の `pnpm-lock.yaml` に `postcss 8.5.24 → 8.5.25` が混入した。
   `git status` を見るまで気付かなかった。
2. **実験条件が成立しないまま誤った陰性結果を出しかけた。** 複製先の `pnpm-workspace.yaml` を
   `minimumReleaseAge: 0` に書き換えて「ゲート無効」条件としたが、pnpm は本体の設定（`10080`）を
   読んでいた。そのため「ゲートを無効にしても nanoid は上がらない」＝「ゲート以外に障害がある」と
   3 回続けて誤判定しかけた。

実際には障害はゲートのみで、cwd を分離し（`mise exec -- bash -c "cd <一時DIR> && pnpm ..."`）
ゲートを `--config.minimumReleaseAge=0` で上書きしたところ、同じコマンドが `3.3.18` に到達した。

発覚の端緒は `pnpm config list` が `minimumReleaseAge: 10080` を返したこと。複製先の同ファイルは
`0` だったため、読まれているファイルが違うと分かった。

## 根本原因

- **なぜ誤ったか**: `mise -C <dir> exec` を「mise の設定を dir から読む（cwd は据え置き）」と解釈した。
  実際は cwd 自体を dir へ変える。
- **なぜ気付かなかったか**: 実験の一発目に「どこで実行されているか」「実験条件が実際に切り替わったか」を
  観測しなかった。複製直後に `pwd` と `pnpm config get minimumReleaseAge` を出していれば初回で分かった。
- **なぜその観測が抜けたか（根本原因）**: AGENTS.md の「調査と実験」は条件・指標・操作の成立を検証する
  規律を持つが、**実験環境の隔離そのものを検証する項目が無い**。「本体を汚さないために複製した」という
  意図が、複製したという事実だけで満たされたと見なされ、検証対象にならなかった。

隔離の失敗は 2 方向に効く点が重要で、本体を壊すだけでなく、**実験条件が成立しないため陰性結果を汚染する**。
既存の「陰性結果には操作の成立確認を付ける」（`2026-08-04-null-result-needs-proof-of-manipulation`）は
「操作が実行されたか」を問うが、今回は操作は実行されており、**実行された場所と設定**が意図と違った。
既存規律ではこの失敗モードを落とせない。

## 横断スコープ

同じ構図を持つのはディレクトリーを指すフラグ全般（`git -C` / `make -C` / `npm --prefix` / `pnpm --dir` /
`docker run -w`）。「設定の参照元だけを変える」のか「cwd ごと変える」のかがフラグごとに違う。
現時点でリポジトリー内のスクリプト・ワークフローにこれらの利用箇所は無い（grep で確認済み）ため、
規律は成果物の修正ではなくエージェントの行動側に効かせる必要がある。

## 提案

実験を一時ディレクトリーへ隔離したら、複製した事実ではなく **実行された場所と実験条件が切り替わったこと**を
一発目に出力して確認してから本番のコマンドを流す。

反映先は `AGENTS.md`「調査と実験」節（一般規律で path を絞れないため rule ではなく基底ドキュメント）。
既存の「操作の成立確認」段落の直後に、4 番目の軸として次を追記する。

```markdown
条件・指標・操作が正しくても、**それが意図した場所で実行されていなければ**結論は誤り、本体も壊れる。
本体を汚さないために複製を作ったら、複製の存在ではなく**隔離が成立したこと**を測る。

- **実験の一発目に、実行された場所と実験条件を出力させる**（`pwd` と、変えたはずの設定値の読み出し）。
  複製を作った・設定ファイルを書き換えたという事実は、隔離の証拠ではない。
- ディレクトリーを指すフラグ（`-C` / `--dir` / `--prefix` / `-w`）は、設定の参照元だけを変えるのか
  **cwd ごと変える**のかを確かめてから使う（例: `mise -C <本体> exec -- pnpm ...` は cwd を本体へ変えるため、
  複製先で実験しているつもりで本体の lockfile が書き換わり、同時に複製先で書き換えた設定は読まれず、
  実験条件が成立しないまま「効かない経路」と誤判定する）。設定だけ借りたいなら `cd` を実験側のシェルに
  閉じ込める（`mise exec -- bash -c "cd <一時DIR> && ..."`）。
- 実験条件の切り替えは、ファイル書き換えよりコマンドラインでの上書きを優先し、**上書きが効いていることを
  読み出して確認**する（`pnpm --config.X=0 config get X`）。
- 実験の後は本体側で `git status` を見る。隔離の失敗は陰性結果を汚染するだけでなく、本体に無言の差分を残す。
```
