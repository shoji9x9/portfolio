# 成功したチェックは「その名の作業を実行した」証拠にならない

## 事象

Dependabot の PR 10 件を `dependabot-merge` で 1 件ずつ手動確認・マージした。作業中、
`gh pr checks` の出力には毎回 `auto-merge=pass` が含まれていたが、それが何をするジョブかを
一度も確認しなかった。作業後にユーザーから「自動マージの設定は入っていないのか」と問われて
初めて `.github/workflows/dependabot-automerge.yml` の存在に気づいた。

実際にはこのワークフローは対象判定のバグ（`packageEcosystem` を実際には返らない `"npm"` と
比較）で全 PR を対象外と判定し、CI 待ちとマージのステップを skip したまま success で終わって
いた。つまり「一度も自動マージしていない」状態が、成功チェックとして表示され続けていた。

## 根本原因

チェック一覧を pass / fail の集計としてしか読まず、各チェックが**何を実行するジョブか**を
確認しなかった。条件不成立で本体ステップを skip してもジョブは success で終わるため、
「success = その名の作業が行われた」と読むと、沈黙した自動化を見逃す。

加えて、手作業を始める前に「その作業を担う自動化が既にリポジトリーにあるか」を確認する段が
どこにも無かった（`dependabot-merge` スキルの手順は CI 成功の確認までで、既存自動化の有無は
問わない）。

同じ沈黙は本ワークフローにもう一段ある。`Dependency Review` は依存マニフェストの変更でのみ
起動するため、Actions のみの更新では起動しないワークフローを 20 分待ってタイムアウトし、
やはり success のまま終わる。失敗が可視化されない設計そのものが共通の原因。

## 提案

成功したチェック・ジョブは「その名の作業を実行した」証拠にならない。条件不成立で本体を
スキップしても success で終わる設計が普通なので、自動化に依存する前・依存を疑うときは
「実際に何をしたか」を実行ログか出力で確認する。あわせて、自分が書く自動化には
**スキップした事実と理由を必ず可視化させる**（無言の skip を残さない）。

反映（機構）: `dependabot-automerge.yml` に判定結果と結末を `$GITHUB_STEP_SUMMARY` へ必ず
書くステップを追加し、「対象外だった」「CI 未達だった」「マージした」のどれなのかを
ジョブを開かずに判別できるようにする。

反映（規律）: `AGENTS.md` に「反復的な手作業を始める前に、それを担う自動化がリポジトリーに
既にあるか（ワークフロー・チェック名）を確認する」を追記する。

## 適用（2026-08-03、Issue #43）

**規律（ドキュメント）と機構（決定論的な可視化）の両方**へ反映した。散文の規律だけでは
確率的にしか守られず、今回まさにその形で見逃したため。

### 1. 機構へ

`dependabot-automerge.yml` に `Report outcome` ステップ（`if: always()`）を追加し、更新内容と
結末（「対象外」「対象だがゲート未達（理由つき）」「マージした」）を `$GITHUB_STEP_SUMMARY` へ
必ず書くようにした。今回の「一度も自動マージしていないのに success」は、この出力があれば
PR 一覧を見た時点で気づけた。判定バグ本体（`packageEcosystem` の比較値）と、Actions のみの更新で
起動しない `Dependency Review` を待ち続けてタイムアウトする問題も同じ commit で修正した。

### 2. 規律へ

`AGENTS.md` の「PR 運用」節へ 2 点追記した（既存の効率系所見の規律と同じ「偽の green」の族のため
同じ節に置いた）。

1. 成功したチェックは「その名の作業を実行した」証拠ではない。実行ログか出力で実際の動作を確認する
2. 反復的な手作業を始める前に、それを担う自動化が既にあるかを確認する

### 横断スコープ

同型の「条件不成立で本体を skip し、ジョブは success」は他ワークフローにもある（`deploy.yml` の
Preview / Production は PR で SKIPPED）。ただしそちらは skip が意図どおりで、かつ skip がチェック
一覧に `SKIPPED` として出るため沈黙しない。今回問題だったのは**ジョブ内でのステップ skip**が
外から見えない点で、対象は本ワークフローに閉じると判断した。
