# リプレイス戦略書（strategy）

- 参照する測定: `.replace/survey.md`（2026-07-28T17:25:07+09:00）
- 決定根拠: Issue #3 のスコープと、上記 survey の実測値。

## 非対称設計

- バックエンド: 該当なし。現行に API、DB、書き込み処理はなく、直接移植するバックエンドはない。
- フロントエンド: Vite + React + TypeScript で実装し、パリティスイートと視覚ベースラインで検証する。Next.js
  コンポーネントの 1:1 diff は正解としない。
- LAPRAS: 外部プレビュー取得を隔離した新側 API 境界として扱う。取得タイミング、キャッシュ、失敗時表示は
  `intentional_diffs.pending` の決定後に実装する。この隔離は独立した横断 API 機能ではなく、`lapras` 機能内の
  先行フェーズ（API を作り切ってから UI）として実現する（fan-out が 1 のため横断 API の基準を満たさない）。

## パリティスイート戦略

- ロケータ方針: role + accessible name を原則とし、id/name をアンカーにしない。
- ロケータマッピング層の規模見積もり: `/` の 134 候補中 128（95.5%）は名前付き。26 の重複ペアと 6
  の名前なしリンクに限定して、順序または近接見出しを使うページ固有マッピングを作る。
- 読み取り側を先行する。書き込み UI・DB がないため、DB 復元や書き込みテストは行わない。
- 現行にフォーム・ダイアログ・複数ページはない。各機能では `/` の該当範囲の ARIA、computed style、
  スクリーンショットを、少なくともデスクトップと狭い viewport で採取する。
- 外部画像は現在の URL と描画可能性を比較する。外部サービスが返すバイナリ自体は正解として固定しない。
- 機能は `static-page` と `lapras` の 2 単位で、いずれも `/` を対象とする。ベースライン採取と `parity-diff` の往復は
  ページ単位で重複するため、`static-page` を先に収束させてから `lapras` を重ねる（依存順 1 → 2）。

## ゴールデンデータセットの方針

- 本番を参照せず一から作る。DB がないため、設定で `dataset_mode: static` を宣言し、投入ツールは
  `dataset_static_paths`（`seed/data/`）配下へ静的データを生成する。
- `golden-dataset` フェーズ A は現行の `services/badges.ts`、`services/careers.ts`、`services/artifacts.ts` と
  ページ内の静的テキストから論理データを再現し、件数・安定 ID・基準データを固定する。生成物の決定論的ハッシュを
  `metadata.json` の `current.fingerprint` に記録する（`static` では投入先環境を持たないため `current.target` と
  `seeded_at` は `null`）。
- フェーズ B は同じ論理データを新側の静的データ形式へ写像して生成し、データ項目と表示順を照合する。
  `static` では全 target が投入対象となり、データセットバージョンの一致は免除されない。
- DB 投入、マスキング、DB リストアは行わない。

## 未検証領域の扱い

- linkpreview.net の生レスポンス、秘密鍵を伴う呼び出し、キャッシュと失敗時表示は `gaps` に記録し、手動検証が必要となる。現行アプリは変更しない。
- アニメーションのパリティは対象外とする。差分比較時にアニメーションが存在すれば停止する。
- 外部画像配信の一時障害は環境ノイズとして分離し、リンク URL・alt・配置はアプリ側の検証対象とする。

## 成果物の扱い

- テキスト成果物: Git で管理する（`.replace/` の survey、strategy、features、および後続のメタデータ）。
- バイナリ成果物: ワークツリーは最新のみ、既定保存先は local、容量閾値は 50 MB。必要な機能だけ Git LFS へ上書きする。

## 実行対象環境

- 現側は `current-prod`（公開中の GitHub Pages）1 環境。読み取り専用で扱い、ベースラインはここから採取する。
- 新側は `local-dev`（既定）・`local-production`・`preview`・`production` の 4 環境。成果物は
  `.replace/parity/<slug>/new/<target>/` に環境別で分かれる。
- `preview` は Cloudflare Pages のデプロイ固有 URL を `url_command`（`node scripts/preview-url.mjs`）で実行時に解決する。
  解決値は成果物へ書かず `"runtime"` を記録する。プレビューは PR 作成時にのみデプロイされるため、PR 作成前の
  ブランチでは解決できず停止する。

## リリース戦略の判断材料

- 現行は GitHub Pages の静的な単一ルートであり、移行先は Cloudflare となる。
- 切替前に、`/` の全セクションの内容・外部リンク・主要 viewport のパリティと、LAPRAS の手動 gap を明示する。
- 外部プレビュー取得方式の決定後に、段階切替か全面切替かを決定する。
