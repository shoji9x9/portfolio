### 実行環境による見た目差（2026-07-29）

**視覚の判定は採取環境に依存する。** ベースラインとパリティスイートは Linux（WSL）の Chromium で
実行しており、ユーザーが日常的に見る Windows の Chrome とはインストール済みフォントが違う。

実際にこの差で 1 件の不具合を見落とした。新側のフォントスタックに `system-ui` を含めていたため、
**Windows では日本語が Yu Gothic UI で描画され**（現行は Noto Sans JP）、プロフィールの値セルが
383px → 305px になっていた。Linux では総称ファミリーの解決先が既定フォントと同じになるため
幅が一致してしまい、実測でも parity-suite でも表面化しなかった（ユーザーの手元での確認で発覚）。

対応は 2 つ:

- 現行のフォントスタック（`Inter, Inter Fallback` の 2 つだけ・総称ファミリー無し）をそのまま再現した。
  日本語グリフを持つファミリーがスタックに無いので、両側ともブラウザーの既定フォントへ落ちる
- `checkFontStackFallsThroughForCjk` を追加し、**スタックに総称ファミリー・システムフォントの
  キーワードが入っていないこと**を決定論的に判定するようにした（幅の比較では環境依存で気づけないため）

残る限界: フォント以外にも環境依存の見た目差はありうる（スクロールバー幅・既定フォントサイズ・
デバイスピクセル比）。`metadata.json` の `capture_conditions.environment` に採取環境を記録してあるが、
**利用者の環境での確認は `browser-test` 等で別途行う必要がある**。

### フォント差の原因調査と対応（2026-07-29・解決済み）

同一ブラウザー・同一 CSS でフォントファイルだけを差し替えて実測した。原因は Inter の版差ではなく
**TrueType のヒンティング命令（`prep` テーブル）の有無**だった。

| ファイル                             | Inter の版 | `prep`   | 16px 小文字 26 文字     |
| ------------------------------------ | ---------- | -------- | ----------------------- |
| 現行（next/font が焼き込んだ woff2） | 3.019      | 無し     | **215px**               |
| `@fontsource-variable/inter@5.0.19`  | 3.019      | 有り     | 224px                   |
| `@fontsource-variable/inter@5.3.0`   | 4.001      | 有り     | 223px                   |
| `inter-ui@4.1.1`（Inter 公式）       | 4.001      | 無し     | 212px                   |
| **`inter-ui@3.19.3`（Inter 公式）**  | **3.019**  | **無し** | **215px（現行と一致）** |

- 現行と `@fontsource-variable/inter@5.0.19` は**同じ Inter 3.019 でグリフの送りも完全同一**
  （`a` 9.03 / `m` 13.92 / `w` 13.00 / `i` 3.80 …が 1 単位まで一致）。にもかかわらず 16px では
  `m` が 13px と 14px に丸まる。`prep` を持つ側でヒンティングが整数丸めを変えるため。
  ヒンティングを止める（`text-rendering: geometricPrecision`）と両者は 221.70px で一致する。
- 版差も独立に効く。ヒンティング無しどうしで比べても 3.019（215px）と 4.001（212px）は違う。
- **したがって一致には「同じ版」かつ「ヒンティング無し」の両方が要る。**

**採った対応**: Inter 公式配布の npm パッケージ `inter-ui@3.19.3` を使う。ヒンティング無し（既定）と
有り（`inter-hinted*.css`）を両方同梱しており、既定側が現行と同じビルドにあたる。
`src/index.css` に `@font-face` を 1 つ書いて `Inter (web latin)/Inter-roman.var.woff2` を参照する。

- 実測: 小文字 26 文字・URL・日本語混在文のすべてで現行と幅が一致
- pnpm 管理のまま（vendoring しない）。ライセンス（OFL）はパッケージの `LICENSE.txt` に含まれる
- バージョンは 3.19.3 に固定する。上げると Inter 4.x になり字形が変わるため、移行完了までは動かさない
- `knip` は CSS の `url()` を追跡しないため `ignoreDependencies` に登録した。実使用は
  `pnpm build` の出力（`dist/assets/Inter-roman.var-*.woff2`）とパリティスイートが担保する

## 本スキルで採らなかった判断（意図的な非対象）

- **セクションを包む要素の role**: 現行は素の `div` で landmark を持たない。手書き aria
  スナップショットではセクション単位でアンカーし、包む要素の role を契約にしていない。新側が
  `<section>`＋見出し関連付け（`role=region`）へ改善しても赤くならない。
- **タブ順の停止数**: 到達可能性と相対順序だけを判定し、停止数の厳密一致は基準にしていない。
- **色値そのもの**: hover・dark の判定は「既定と変わること」までで、具体的な色値は契約にしていない
  （Tailwind v4 のパレット差を潰さないため）。色値の差は `parity-diff` の差分器が扱う。
- **プロフィール表を `<table>` で表すこと**: これは契約に**した**。表形式データの行・列関係を
  スクリーンリーダーで辿れることは提示方法の仕様であり、失うとアクセシビリティの退行になるため。
  新側で別構造にしたい場合は `component_diffs` での宣言が要る。
